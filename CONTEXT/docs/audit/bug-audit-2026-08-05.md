# Bug Audit — Browser Battle Royale

**Date:** 2026-08-05  
**Type:** review only (no fixes — planning/review mode)  
**Scope:** `src/`, `nakama/modules/` — three parallel audit passes + manual verification of every CRITICAL/HIGH finding against the actual code and Nakama 3.22 docs.

Severity: **CRITICAL** = crash/data loss · **HIGH** = wrong behavior · **MEDIUM** = edge case · **LOW** = cosmetic/perf.

## CRITICAL

### C1. Online matches never receive snapshots — `src/net/client.ts:86`
`MatchClient.connect()` (online path) connects the socket but **never registers `socket.onmatchdata`**. `handleSnapshot()` is only wired to the `LocalServer` callback (`client.ts:76`). A grep for `onmatchdata` across `src/` returns nothing. The Lua server broadcasts `OP_SNAPSHOT` (match_handler.lua:419), but the client ignores all match messages → **online play is broken**: no remote rendering, no self-correction, frozen zone/loot. The `nakama-integration` CI job would catch this only if `sim:nakama` exercises the real socket path.
**Fix:** register `socket.onmatchdata = (m) => { if (m.op_code === OP_SNAPSHOT) this.handleSnapshot(decodeSnapshot(m.data)); }` in `connect()` (online branch), and decode via the protocol module.

### C2. Leaderboard is never created; every submission throws — `nakama/modules/leaderboard.lua:11`
`nk.leaderboard_create(LEADERBOARD_ID, false, 0, "best", 0, "{}")` passes numeric `0` for the **sort** and **reset** args. Nakama 3.22 (pinned in docker-compose.yml) Lua signature is `leaderboard_create(id, authoritative, sort, operator, reset, metadata)` where `sort` is the string `"desc"`/`"asc"` and `reset` is a CRON string. The type error is swallowed by `pcall` (`leaderboard.lua:11`), so the board silently never exists, and `submit_score`'s unguarded `nk.leaderboard_record_write` (line 62) then throws for the missing board → **every online leaderboard submission fails**.
**Fix:** `nk.leaderboard_create(LEADERBOARD_ID, true, "desc", "best", "", "{}")` and don't pcall-swallow creation failure (log + rethrow).

## HIGH

### H1. Vehicle occupants take storm damage twice per frame — `src/gameplay.ts:695`
`updateVehicles` applies zone damage to occupants (line 695) while `updateZone` (line 650) damages the same unit again because its position equals the vehicle position. Two independent zone-damage paths hit the same player each tick.
**Fix:** delete the zone-damage block in `updateVehicles`; `updateZone` already covers occupants.

### H2. Minimap storm circle / zone timer / storm indicator all frozen — `src/game.ts:374,862,886,916`
`MatchGame` calls only `zoneSys.updateFromZone(...)` (game.ts:374) which moves the ring mesh but **never advances `phaseTime`** (`ZoneSystem.update()` is never called). So `zoneSys.innerRadius` is frozen at the initial 480, `phaseTotalDuration - phaseTime` is always 200s, and `isOutsideZone` uses the frozen radius. Result: the minimap circle never shrinks, the zone timer never counts down, and the STORM indicator never appears once the real zone shrinks past the player.
**Fix:** read these from `this.sim.zone` (the authoritative `ZoneLogic` advanced in `gameplay.ts:636`) instead of the render-only `zoneSys`.

### H3. Right-click aim never triggers — `src/input.ts:58`
`aim` reads `keys.has('MouseRight')`, but mouse buttons fire `mousedown`, not `keydown`, and only button 0 is handled. FPS/aim toggle via right-click is dead code.
**Fix:** add a `mousedown` handler for `e.button === 2` (gated on pointer lock), mirrored to `keys`.

### H4. `flushInputs` drops ~2/3 of mouse look — `src/net/client.ts:122`
`flushInputs` keeps only `frames[frames.length - 1]` per 20 Hz tick, discarding per-frame `mouseX` deltas between ticks. At 60 fps the client predicts with a fraction of the actual look delta; remotes see jerky turning.
**Fix:** merge the batch — sum `mouseX`/`mouseY` deltas, take the latest button state, then send once per tick.

### H5. Double survivor-decrement on zone kills — `nakama/modules/match_handler.lua:600`
A player killed by a shot while outside the zone gets `alive_count` decremented a second time by the zone branch (health already ≤ 0), under-counting survivors and tripping premature win detection.
**Fix:** guard the zone-kill decrement with an alive check.

### H6. Stale cached socket reused after disconnect — `src/net/nakama.ts:49`
`connectSocket` returns the module-cached `socket` without checking it's still connected. After `MatchClient.dispose()` disconnects it, a later online session reuses the dead socket and fails to join.
**Fix:** null the cached socket on disconnect (or reconnect before returning).

### H7. Lobby overlay never removed in online flow — `src/main.ts:174`
`joinOnlineMatch`/`launchOnlineMatch` never remove the `#lobby-overlay` DOM element (unlike the local path, which removes it before Play Local — `lobby.ts:193`). The opaque full-screen overlay (z-index 9998) sits over the online game canvas → online match invisible/unplayable until it ends.
**Fix:** remove/hide the overlay in `launchOnlineMatch` before `onlineGame.start()`.
